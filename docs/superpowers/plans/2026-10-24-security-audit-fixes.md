## Rulings on the open decisions (controller's calls — user can overturn)

- R1 Release signing (finding M9): ECDSA P-256 signature over `SHA256SUMS` → `SHA256SUMS.sig` (DER, verified with `openssl dgst -sha256 -verify`). Public key embedded in `install.sh`, `install.ps1` (verified with .NET `ECDsa`), and `dpm-custody`. CI signs with secret `RELEASE_SIGNING_KEY` (PEM). Upgrade verifies with the key embedded in the *installed* `dpm-custody`. Missing SHA256SUMS or signature is fatal. `DPM_CUSTODY_RELEASE_PUBKEY` (path to a PEM) overrides the embedded key, for local rehearsals only. The production key pair is generated by the user (a `scripts/release-signing-key.sh` helper prints the commands); until then the embedded key is a clearly-marked placeholder and the README says so.
- R2 Backup encryption (finding M10): hybrid X25519 + AES-256-GCM done by node inside the manager image (`setup backup-seal` / `backup-open`), streamed via `docker compose run --rm --no-deps setup`. Setup creates a recovery key pair at install; the private part is shown once in the setup kit as a "backup recovery key" and only the public part is kept. Existing installs: `./dpm-custody backup-key` creates it; until then backups stay plaintext with a loud warning. Keep newest `DPM_CUSTODY_KEEP_BACKUPS` (default 5).
- R3 (DROPPED by the user 2026-10-24 — no rate limits or withdrawal caps in dpm-wallet) dpm-wallet in-service limits (finding M15): `@nestjs/throttler` on `/sign/*` and `/meta-tx/*` (`SIGN_RATE_LIMIT_PER_MIN`, default 600); optional `WITHDRAW_RECIPIENT_ALLOWLIST` (comma list; empty = off); optional `WITHDRAW_MAX_DAILY_DECIMAL` global rolling-24h cap (empty = off). Defaults never break current flows.
- R4 Setup worker (finding M11): the worker keeps running (user accepted that design earlier). Instead: the manager drops reliance on `DPM_WALLET_MANAGER_BOOTSTRAP_ADMIN_KEY` after adoption and setup removes it from `dpm-wallet-manager.env`; setup-state stops holding admin/operator/builder keys once setup completes and the owner has seen the kit (the kit then tells them to reveal keys in the admin UI). Admin key is not revoked — it is the operator's working credential.
- R5 Archive deletion (finding L-archive): minimum age for deleting records raised to 30 days; no two-admin confirmation (single-admin installs are normal).
- R6 dpm-wallet failure log dump (finding M14): public repo artifacts are readable too, so print pod status + events + only the last 50 lines filtered to error level, never full logs.
- R7 `pg-data:/storage/pg:ro` on the manager stays: storage monitoring needs statfs on it.
